# Политика безопасности

Безопасность является частью продукта Lk_uni и рассматривается наравне с функциональностью.

## Сообщение об уязвимости

Не публикуйте сведения о потенциальной уязвимости в открытом GitHub Issue.

До настройки отдельного приватного канала GitHub Security Advisories направляйте минимальное описание владельцу репозитория через профиль GitHub, не раскрывая эксплуатационные детали публично.

Сообщение должно содержать:

- затронутый компонент и версию;
- условия воспроизведения;
- ожидаемое и фактическое поведение;
- оценку возможного влияния;
- безопасный минимальный пример воспроизведения;
- предлагаемый способ связи.

## Обработка

После получения сообщения команда:

1. подтверждает получение;
2. проверяет воспроизводимость;
3. оценивает серьёзность и область воздействия;
4. готовит исправление и тесты;
5. публикует обновление и рекомендации после устранения риска.

## Область особого внимания

- обход аутентификации;
- межпроектный доступ к данным;
- кража или повторное использование токенов;
- нарушение ротации refresh-токенов;
- повышение привилегий;
- раскрытие секретов или персональных данных;
- подмена identity;
- отсутствие аудита критического действия.

## Поддерживаемые версии

До первого публичного релиза поддерживается только актуальное состояние ветки `main`. Политика поддержки версий будет формализована перед `v1.0.0-alpha`.
