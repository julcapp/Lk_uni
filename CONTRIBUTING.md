# Участие в разработке Lk_uni

Спасибо за интерес к проекту.

## Перед началом работы

1. Проверьте существующие Issues и Pull Requests.
2. Для существенного изменения сначала создайте Issue и согласуйте подход.
3. Не включайте секреты, персональные данные и production-конфигурацию.

## Локальная разработка

```bash
git clone https://github.com/julcapp/Lk_uni.git
cd Lk_uni
git checkout -b feature/short-description
```

Инструкции backend находятся в `backend/README.md`.

## Ветки

- `feature/...` — функциональность;
- `fix/...` — исправления;
- `docs/...` — документация;
- `chore/...` — инфраструктурные изменения;
- `security/...` — согласованные security-исправления без раскрытия уязвимости.

## Коммиты

Используйте понятные сообщения в формате Conventional Commits:

```text
feat: add email identity verification
fix: reject expired refresh token
docs: document session revocation
```

## Pull Request

PR должен:

- решать одну связанную задачу;
- содержать описание причины и результата;
- включать тесты для изменённого поведения;
- обновлять документацию и CHANGELOG при необходимости;
- проходить CI;
- не содержать секретов.

## Definition of Done

Изменение считается завершённым, когда готовы:

- реализация;
- позитивные и негативные тесты;
- документация;
- запись в CHANGELOG;
- успешный CI;
- понятный Pull Request.

## Стиль взаимодействия

Обсуждайте решения предметно и уважительно. Критикуйте код и идеи, а не участников.
