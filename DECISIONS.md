# Lk_uni — журнал принятых решений

Этот файл является кратким реестром утверждённых продуктовых и архитектурных решений. Подробное обоснование хранится в `docs/adr/`.

| № | Решение | Статус |
|---:|---|---|
| 001 | Lk_uni развивается как самостоятельная Identity Platform, а не только форма входа | Принято |
| 002 | Целевая СУБД — PostgreSQL; MySQL считается legacy | Принято |
| 003 | Пользователь имеет неизменяемый Identity ID; email и телефон являются изменяемыми identities | Принято |
| 004 | MAX — один из каналов регистрации, входа, восстановления и уведомлений; обязательность задаётся проектом | Принято |
| 005 | Первый и единственный tenant Demo v0.1 — DevHub | Принято |
| 006 | Сначала создаётся Demo v0.1, затем Production Core | Принято |
| 007 | Demo и Production должны использовать одно ядро и различаться конфигурацией провайдеров | Принято |
| 008 | В пользовательской форме нет технического поля `project`; контекст приходит из конфигурации | Принято |
| 009 | Поле имени в текущем DevHub Demo принимает кириллицу, цифры, пробел и дефис | Принято |
| 010 | Email проверяется на латинский формат, наличие `@` и доменной части | Принято |
| 011 | В Demo согласия могут быть предустановлены; в Production пользователь ставит их самостоятельно | Принято |
| 012 | Обязателен Account Recovery через подтверждённые identities | Принято |
| 013 | Постоянные пароли не отправляются по email или мессенджерам | Принято |
| 014 | Основной Recovery Flow — подтверждение личности и самостоятельное создание нового пароля | Принято |
| 015 | Временный пароль допускается только как отдельная enterprise-политика с TTL и обязательной сменой | Принято |
| 016 | Session Management включает idle timeout, absolute timeout и предупреждение перед завершением | Принято |
| 017 | Типовой idle timeout кабинета — 30 минут; конкретное значение настраивается tenant-политикой | Принято |
| 018 | После восстановления доступа старые сессии по умолчанию отзываются | Принято |
| 019 | Пользователь не видит технических ошибок; каждая ошибка содержит понятное следующее действие | Принято |
| 020 | Communication Hub работает событийно и поддерживает email, MAX, Telegram и Internal Inbox | Принято |
| 021 | Обычные входы не должны создавать лишний поток писем; уведомляются первый вход, новое устройство и рисковые события | Принято |
| 022 | Lk_uni не хранит бизнес-данные проектов | Принято |
| 023 | Расширения профиля проекта реализуются через claims | Принято |
| 024 | API версионируется с префиксом `/api/v1` | Принято |
| 025 | Developer Sandbox входит в продукт и содержит API Explorer, события, настройки и симулятор ошибок | Принято |
| 026 | Текущая синяя/графитовая цветовая палитра PAL сохраняется как базовая Design System | Принято |
| 027 | Standalone Mode требует отдельного ADR до реализации | На обсуждении |
| 028 | Identity Federation, SSO и OIDC реализуются после проверки Demo v0.1 | Отложено |
| 029 | Доступ разделён на три изолированных контура: User App, Project Admin App и Platform Owner Console | Принято |
| 030 | Первый ChatGPT App преимущественно read-only и работает только с данными текущего пользователя | Принято |
| 031 | Концептуальные, архитектурные и глобальные настройки Lk_uni не публикуются в пользовательской MCP-поверхности | Принято |
| 032 | Миграции PostgreSQL реализуются через Knex, подключение — через официальный драйвер pg | Принято |

## Правило ведения

Новое решение считается архитектурно принятым после:

1. обсуждения;
2. записи в этот реестр;
3. создания или обновления ADR;
4. отражения в Roadmap и Demo-сценарии, если решение влияет на пользователя.
