# Итерация 003 — Совершенствование репозитория

## Статус

Активна.

## Цель

Довести GitHub-репозиторий Lk_uni до профессионального уровня open source продукта: сделать назначение проекта понятным с первого экрана, упорядочить документацию, закрепить правила работы и подготовить репозиторий к публичному alpha-релизу.

## Область работ

### 1. Главная страница репозитория

- профессиональная структура README;
- чёткое позиционирование Identity Platform;
- описание текущего статуса;
- таблица возможностей;
- схема архитектуры;
- быстрый старт;
- навигация по документации;
- Definition of Done;
- предупреждение о статусе лицензии.

### 2. Управление репозиторием

- защита ветки `main`;
- слияние только через Pull Request;
- обязательные проверки перед слиянием;
- правила разрешения обсуждений;
- настройка Description и Topics;
- подготовка системы Labels и Milestones.

### 3. Developer Experience

- воспроизводимый локальный запуск;
- единая точка входа в документацию;
- понятная структура каталогов;
- примеры интеграции;
- OpenAPI и интерактивная документация;
- будущие SDK и готовые виджеты.

### 4. Документация

- актуализация архитектуры;
- журнал архитектурных и продуктовых решений;
- описание контуров доступа;
- модель данных;
- Auth Flow и Account Recovery;
- порядок поддержки и раскрытия уязвимостей.

## Результаты итерации

Итерация считается завершённой, когда:

- README корректно отображается в `main`;
- Description и Topics репозитория соответствуют позиционированию;
- ветка `main` защищена;
- документация не содержит явных противоречий;
- создан набор приоритетных Issues следующего этапа;
- выбран и добавлен файл `LICENSE`;
- подготовлен план первого публичного alpha-релиза.

## Не входит в итерацию

- разработка новых функциональных модулей Auth Core;
- подключение боевых внешних провайдеров;
- выпуск production-версии;
- создание новых репозиториев.

## Риски

- обязательные status checks нельзя включать до появления стабильных проверок для всех PR;
- требование внешнего одобрения блокирует работу единственного владельца репозитория;
- преждевременный выбор лицензии может ограничить будущую коммерческую модель;
- визуальные материалы не должны создавать впечатление готового production-релиза.

## Следующие решения владельца продукта

1. Выбор лицензии: Apache-2.0, MIT или иная модель.
2. Утверждение состава первого alpha-релиза.
3. Решение о публичном демонстрационном стенде.
4. Решение о сроке публикации SDK.
