# Архитектурные инварианты Lk_uni

**Статус:** принят  
**Область действия:** вся платформа Lk_uni  
**Изменение документа:** только через отдельное архитектурное решение (ADR)

## Назначение

Этот документ фиксирует правила, которые должны сохраняться независимо от версии, состава модулей и конкретной реализации платформы.

## LAI-001. Единое ядро платформы

В системе существует один Platform Kernel. Он отвечает за загрузку платформы, регистрацию модулей, жизненный цикл сервисов и глобальную конфигурацию. Модули не создают собственные конкурирующие ядра.

## LAI-002. Единая цифровая личность пользователя

Пользователь имеет один глобальный идентификатор. Он может состоять в нескольких организациях, использовать несколько проектов, иметь разные роли и способы входа, но не дублируется как отдельная личность для каждого проекта.

## LAI-003. Изоляция проектов

Проект не получает прямой доступ к данным другого проекта. Межпроектное взаимодействие допускается только через явно разрешённые публичные интерфейсы платформы с обязательной проверкой прав и аудитом.

## LAI-004. Отсутствие предметной логики в ядре

Platform Kernel содержит только инфраструктурные механизмы. CRM, торговля, вендинг, склад, документооборот и иная предметная логика реализуются в подключаемых проектах или самостоятельных модулях.

## LAI-005. Самостоятельность модулей

Каждый модуль имеет собственные границы ответственности, документацию, тесты, версию и журнал изменений. Скрытые циклические зависимости между модулями запрещены.

## LAI-006. Контрактное взаимодействие

Внешние проекты и модули используют только публичные API, SDK и события. Обращение к внутренним классам, таблицам или приватным функциям другого модуля запрещено.

## LAI-007. Версионирование и обратная совместимость

Публичные контракты версионируются. Несовместимые изменения требуют новой версии API, миграционного периода и документированного порядка вывода старой версии из эксплуатации.

## LAI-008. Синхронность кода и документации

Архитектурное изменение не считается завершённым, пока не обновлены соответствующий ADR, описание API, архитектурная документация и CHANGELOG.

## LAI-009. Наблюдаемость

Каждый исполняемый модуль предоставляет сведения о версии, проверку состояния, структурированные журналы и безопасную диагностику конфигурации без раскрытия секретов.

## LAI-010. Безопасность по умолчанию

Новая возможность проектируется с учётом аутентификации, авторизации, изоляции данных, аудита и безопасных значений по умолчанию. Доступ запрещён, пока он явно не разрешён.

## Контроль соблюдения

Нарушение любого инварианта должно быть выявлено на этапе проектирования, проверки Pull Request или архитектурного аудита. Исключения допускаются только на основании принятого ADR с оценкой последствий и планом устранения технического долга.
