# ADR-0004. Версионирование публичного API

## Статус

Принят.

## Контекст

Lk_uni должна обслуживать несколько клиентских проектов и интеграций, которые обновляются независимо. Несовместимые изменения без явного версионирования создадут риск поломки внешних клиентов.

## Рассмотренные варианты

1. Не версионировать API до первого стабильного релиза.
2. Использовать только версию в HTTP-заголовках.
3. Использовать явную основную версию в URL и дополнительно версионировать схемы событий и SDK.

## Решение

Принят вариант 3.

Публичные REST API публикуются по маршрутам вида `/api/v1/...`. Несовместимые изменения требуют новой основной версии. Совместимые дополнения допускаются внутри текущей версии при сохранении существующих контрактов.

События и SDK версионируются независимо, но должны явно указывать совместимость с версией платформы и API.

## Последствия

Положительные:
- предсказуемая обратная совместимость;
- возможность параллельной поддержки клиентов;
- понятная политика вывода устаревших контрактов.

Отрицательные:
- необходимость временной поддержки нескольких версий;
- дополнительные тесты и документация;
- требуется политика устаревания.

## Контроль соблюдения

Любое изменение публичного контракта должно классифицироваться как совместимое или несовместимое. Несовместимое изменение без новой основной версии запрещено.
