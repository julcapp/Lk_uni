# ADR-0002. Единая система модулей

## Статус

Принят.

## Контекст

Платформа должна подключать Auth Core, Identity Service, аудит, уведомления, настройки и будущие расширения без жёсткого связывания внутренних реализаций.

## Рассмотренные варианты

1. Прямые импорты между модулями.
2. Неформальные соглашения без машинно-читаемого описания.
3. Единый манифест модуля, публичные контракты и регистрация через Platform Kernel.

## Решение

Принят вариант 3.

Каждый платформенный модуль обязан иметь `module.json`, содержащий как минимум:
- уникальный идентификатор;
- отображаемое название;
- версию;
- совместимую версию платформы;
- обязательные зависимости;
- предоставляемые сервисы;
- публикуемые события;
- необходимые разрешения.

Модуль проходит стадии проверки, регистрации, инициализации, запуска, остановки и выгрузки. Прямой доступ к внутренним данным другого модуля запрещён.

## Последствия

Положительные:
- проверяемые зависимости;
- возможность автоматической диагностики;
- изолированное тестирование;
- основа для будущей системы расширений.

Отрицательные:
- дополнительные требования к структуре каждого модуля;
- необходимость версионирования контрактов;
- требуется обработка циклических и отсутствующих зависимостей.

## Контроль соблюдения

CI должен проверять схему `module.json`, уникальность идентификаторов, совместимость версий и отсутствие циклических зависимостей.
