# ADR-0001. Единое ядро платформы

## Статус

Принят.

## Контекст

Lk_uni развивается от демонстрационного приложения к универсальной платформе для нескольких проектов. Без единой точки загрузки, регистрации сервисов и управления жизненным циклом модули будут формировать собственные механизмы запуска и конфигурации.

## Рассмотренные варианты

1. Оставить независимый запуск каждого модуля.
2. Сразу разделить систему на отдельные микросервисы.
3. Создать единое модульное ядро внутри текущего приложения с возможностью последующего выделения сервисов.

## Решение

Принят вариант 3.

Platform Kernel является единственной точкой запуска платформы и отвечает только за инфраструктурные функции:
- загрузку проверенной конфигурации;
- обнаружение и регистрацию модулей;
- построение графа зависимостей;
- запуск и остановку компонентов;
- регистрацию диагностического состояния.

Kernel не содержит предметную логику, данные профиля пользователя, правила конкретных проектов и реализацию способов аутентификации.

## Последствия

Положительные:
- единый жизненный цикл;
- предсказуемый порядок запуска;
- снижение связанности;
- возможность постепенного выделения сервисов.

Отрицательные:
- требуется формальный контракт модулей;
- ошибки Kernel могут влиять на всю платформу;
- необходимо строго контролировать его границы.

## Контроль соблюдения

Изменения, добавляющие предметную логику в Platform Kernel или создающие второе ядро, требуют нового ADR и пересмотра архитектурных инвариантов.
