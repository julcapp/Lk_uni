# UI Prototype Lk_uni v1.0

## 1. Назначение

Первый интерфейсный прототип Lk_uni находится в:

```text
frontend/LkUniPrototype.jsx
frontend/LkUniPrototype.css
```

Прототип показывает целевую логику личного кабинета как универсальной Identity Platform.

## 2. Экраны

### 2.1. Вход

Экран: `LOGIN`

Функции:

- ввод email/телефона/идентификатора;
- вход через email;
- вход через телефон;
- вход через MAX;
- вход через Telegram;
- вход через VK ID;
- вход через SberID;
- переход к восстановлению доступа;
- переход к регистрации.

### 2.2. Регистрация

Экран: `REGISTER`

Функции:

- ввод имени;
- отображение project slug;
- ввод email;
- ввод телефона;
- согласие на обработку персональных данных;
- переход к выбору канала подтверждения.

### 2.3. Выбор способа подтверждения

Экран: `VERIFY`

Функции:

- выбор email;
- выбор телефона;
- выбор MAX;
- отображение policy проекта `required_verification.mode = one_of`.

### 2.4. Подтверждение через MAX

Экран: `MAX`

Функции:

- отображение MAX deeplink / QR-зоны;
- отображение срока жизни challenge;
- отображение назначения challenge: registration / login / recovery;
- переход к альтернативному способу подтверждения.

### 2.5. Восстановление доступа

Экран: `RECOVERY_START`

Функции:

- ввод любого известного идентификатора;
- безопасное сообщение без раскрытия факта существования аккаунта;
- переход к вариантам восстановления.

### 2.6. Выбор способа восстановления

Экран: `RECOVERY_OPTIONS`

Функции:

- маскированный email;
- маскированный телефон;
- восстановление через MAX;
- восстановление через Telegram.

### 2.7. Профиль пользователя

Экран: `PROFILE`

Функции:

- отображение пользователя;
- статус пользователя;
- список связанных identities;
- verified/not linked;
- привязка MAX;
- активные сессии;
- журнал входов.

### 2.8. Админ-настройки проекта

Экран: `ADMIN`

Функции:

- включение/отключение провайдеров;
- email;
- phone;
- MAX;
- Telegram;
- VK ID;
- SberID;
- отображение verification policy;
- сохранение настроек проекта.

## 3. Принятый UX-принцип

Пользователь не обязан помнить отдельный логин.

Вход и восстановление строятся вокруг подтверждённых identities:

```text
email / phone / max / telegram / vk / sberid
```

## 4. Что нужно сделать при переводе прототипа в рабочий UI

- Подключить API `/api/projects/public/:slug`.
- Загружать branding проекта.
- Загружать enabled providers.
- Использовать `/api/auth/register`.
- Использовать `/api/auth/login`.
- Использовать `/api/auth/verify/start`.
- Использовать `/api/auth/verify/status`.
- Использовать `/api/auth/max/start`.
- Использовать `/api/auth/recovery/start`.
- Использовать `/api/auth/recovery/:id/options`.
- Использовать `/api/auth/me`.
- Добавить обработку ошибок API.
- Добавить loading states.
- Добавить route-based навигацию.
- Добавить dark theme.

## 5. Решение

`LkUniPrototype` является первой визуальной базой интерфейса Lk_uni v1.0.

Старый `RegisterForm.jsx` пока не удаляется и остаётся как v0.1 legacy form.
