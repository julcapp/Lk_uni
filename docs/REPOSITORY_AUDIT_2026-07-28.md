# Аудит репозитория Lk_uni

**Дата:** 28.07.2026  
**Область:** `main`, документация, основные конфигурации, Issues и Pull Requests  
**Тип проверки:** статический аудит GitHub без локального выполнения runtime

## Итог

Репозиторий содержит первую рабочую вертикаль PostgreSQL Auth Core и развитую архитектурную документацию. До начала новых модулей необходимо подтвердить воспроизводимость существующего backend, frontend и ChatGPT App.

## Выявленные несоответствия

1. README ссылался на отсутствующий `backend/README.md`.
2. Recovery был указан как готовая возможность, хотя рабочий процесс не подтверждён.
3. README, Roadmap и `PROJECT_STATUS.md` задавали конкурирующие направления развития.
4. Существовал риск параллельного создания второго Auth Core через новую структуру Kernel/Identity.
5. Первая alpha-версия была обозначена как `v1.0.0-alpha`, что не соответствует текущей зрелости.
6. Воспроизводимость чистого клона пока не подтверждена фактическими результатами выполнения команд.
7. Frontend использует зависимости `latest`; версии должны быть закреплены после проверки lock-файла и сборки.
8. OpenAPI отсутствует как исполняемый контракт.
9. Негативные сценарии Auth Core покрыты не полностью.

## Исправлено в baseline PR

- добавлено руководство backend;
- синхронизированы README, Roadmap и статус проекта;
- введено явное разделение «реализовано / частично реализовано / запланировано»;
- Recovery обозначен как обязательный, но незавершённый модуль;
- выбран единый implementation-first путь;
- зафиксировано эволюционное выделение Kernel и Identity из текущего backend;
- целевая версия исправлена на `v0.1.0-alpha`;
- обновлена история изменений.

## Требует фактического испытания

- `npm ci` в backend;
- `npm run db:test`;
- `npm run auth:test`;
- запуск PostgreSQL 16;
- миграции и seed на чистой базе;
- `npm run db:check`;
- запуск backend и проверка `/health`;
- установка и production build frontend;
- проверка ChatGPT App;
- проверка GitHub Actions текущего PR.

Результаты выполнения должны фиксироваться в Issues #5, #7, #8, #9, #10 и #11. Обнаруженные дефекты оформляются отдельными Issues.
